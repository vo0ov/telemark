# AGENTS.md

Рекомендации для ИИ-агентов и разработчиков, работающих с Telemark.

## 🎯 Назначение проекта

Telemark — статический HTML-редактор и приближённый предпросмотр сообщений для Telegram. Пользователь редактирует HTML, видит результат и копирует разметку в буфер обмена для вставки в поддерживаемый редактор Telegram Desktop. Telemark не отправляет сообщения и не гарантирует совпадение предпросмотра с каждым клиентом Telegram.

## 🏛 Структура

- `index.html` — страница, стили, демонстрационный документ и клиентская логика. Это точка входа GitHub Pages.
- `README.md` — описание проекта, возможности и локальный запуск.
- `assets/screenshots/` — изображения для документации.
- `.github/` — шаблоны Issue и Pull Request.
- `LICENSE` и `CONTRIBUTING.md` — лицензия и рекомендации участникам.

Проект не требует серверной сборки. Сохраняйте возможность публикации статических файлов из корня репозитория; не добавляйте систему сборки или зависимости без необходимости и согласования задачи.

## 🚀 Локальная работа

```bash
python3 -m http.server 8000
```

Откройте `http://localhost:8000`. Копирование через Clipboard API требует защищённого контекста и может требовать разрешения браузера. Формулы загружают KaTeX с jsDelivr, а карта — OpenStreetMap; учитывайте доступность сети и сторонних ресурсов.

## 🧭 Правила изменений

- Сначала изучите существующий код и состояние файлов; сохраняйте изменения пользователя и редактируйте только необходимое.
- Разделяйте исходный HTML редактора и представление: обёртки предпросмотра, подсветка, частицы, карта, кнопки и служебные элементы не должны попадать в копируемый HTML.
- Кнопка копирования передаёт `text/html` и `text/plain`. Не заявляйте о работе в Telegram, пока не проверили вставку в нужный клиент и редактор.
- Предпросмотр — приближение, а не точная реализация Telegram. Новые конструкции и ограничения сверяйте с источниками и отмечайте различия между браузером и Telegram.
- Сохраняйте текущее оформление сообщения, когда задача относится только к интерфейсу сайта, и наоборот. Интерфейс должен оставаться удобным на компьютере и телефоне.
- Текст и настройки хранятся в `localStorage` под ключами `telemark-`. Не меняйте их без миграции; при изменениях сброса проверяйте, какие данные он затрагивает.
- Учитывайте работу клавиатуры, фокус и читаемые подписи кнопок. Сохраняйте доступность и возможность отменить вставку в редакторе.
- Считайте вводимый HTML недоверенным: не добавляйте выполнение скриптов или обработчиков из пользовательского ввода и не представляйте предпросмотр как полноценный механизм безопасности.
- Не включайте в репозиторий приватные данные и токены. Учитывайте лицензии сторонних ресурсов.
- При изменениях возможностей обновляйте README и подсказки, если они перестали соответствовать реализации.

## 🧪 Проверка

Выбирайте проверки по масштабу изменения. Для интерфейса проверьте соответствующий сценарий в браузере, включая мобильную компоновку, когда она затронута. Для правок копирования отдельно проверьте содержимое буфера и, если доступно, вставку в конкретный редактор Telegram. Явно сообщайте, что не удалось проверить; не делайте вывод о работе Telegram только по предпросмотру.

## 📝 Протокол коммитов

Когда создание коммита запрошено или разрешено, используйте формат как в `max-bot`: эмодзи, тип и краткое описание, затем обязательное подробное описание после пустой строки.

```text
✨ feat: add HTML insertion menu

- Add categorized insertion options for common blocks.
- Preserve editor selection and undo behavior.
```

Типы:

- ✨ `feat` — новая возможность.
- 🐛 `fix` — исправление ошибки.
- ♻️ `refactor` — изменение структуры без новой возможности или исправления ошибки.
- 📝 `docs` — документация.
- 🎨 `style` — оформление и форматирование.
- 🔧 `chore` — обслуживание проекта и конфигурация.
- ✅ `test` — добавление или исправление проверок.

Используйте конкретное описание и правдивый список изменений. Не создавайте коммиты, не публикуйте и не отправляйте изменения без соответствующего запроса или разрешения.
